# 06 · 系统架构

## 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | React 18 + TypeScript + Vite 5 + Tailwind 3 | TanStack Query 管数据流；轻量自研 i18n（中/英）；Recharts 图表 |
| 后端 | Python 3.13 + FastAPI + Pydantic 2 | 分层：api/routes → services → models |
| ORM | SQLAlchemy 2.0（Mapped 声明式） | `TZDateTime` TypeDecorator 统一 SQLite/PG 时区行为 |
| 迁移 | Alembic | `render_as_batch` 兼容 SQLite；init_db 失败时 create_all+stamp 兜底 |
| 数据库 | SQLite（默认）/ PostgreSQL（生产） | 差异封装在 database.py 与 TypeDecorator |
| 异步 | 第一版同步执行 | 服务层函数无 HTTP 依赖，未来可包成 Celery 任务；Redis 不可用不影响核心 |

## 模块划分

```
backend/app/
├── main.py            FastAPI 实例、统一错误信封、安全响应头、健康检查
├── config.py          pydantic-settings，.env 加载
├── database.py        engine/session（SQLite pragma、WAL）
├── security.py        PBKDF2-SHA256 口令 + JWT
├── deps.py            get_current_user / OrgScope（组织隔离在依赖层强制）
├── models/            27 张表（org/customer/inquiry/requirement/product/quote/...）
├── services/
│   ├── normalization.py   多语言归一化字典层（颜色/材质/币种/国家/港口/认证/同义词）
│   ├── slot_extractor.py  规则槽位提取（EN/ZH）
│   ├── requirement_engine.py  纯逻辑多轮状态机
│   ├── requirement_service.py DB 适配（ingest/manual/history/recompute）
│   ├── fields.py          字段定义单一事实源 + 完整度算法
│   ├── summary.py         确定性中文摘要
│   ├── matching.py        两阶段匹配（召回+可解释重排序+硬条件）
│   ├── clarification.py   追问推荐（阻塞>矛盾>信息增益>偏好）
│   ├── quotation.py       确定性报价计算器
│   ├── reply_drafts.py    10 类回复模板（EN+ZH、事实溯源）
│   ├── ingestion.py       统一摄取管道（幂等、客户自动关联）
│   ├── connectors/        连接器注册表 + 邮箱/WhatsApp 模拟 + 表单/Webhook
│   ├── ai/                AI 适配层（none/openai_compat/ollama，白名单校验）
│   └── followup.py        线索评分、工作量清单、任务建议
└── seed/              演示数据（贴近真实业务）
```

## 核心数据流（询盘闭环）

```
外部消息/手动粘贴
   → ingestion.ingest_external_message / add_message     (幂等去重)
   → slot_extractor.extract_slots                        (规则提取)
   → requirement_engine.apply_updates                    (多轮状态、锁定、冲突)
   → fields.completeness_breakdown + summary.build_summary
   → matching.persist_match_results                      (召回+重排序)
   → clarification.recommend                             (一个主问题)
   → quotation.compute_quote                             (确定性计算, 人工批准)
   → reply_drafts.generate_draft                         (EN+ZH, 事实溯源)
   → followup.create_task / workload_lists               (提醒)
```

## 错误与可观测性

- 统一错误信封 `{"error": {"code","message","details"}}`（校验失败 422 亦同构）；
- 审计日志记录登录、导入提交、报价创建/批准、草稿批准、连接器操作等（敏感字段脱敏）；
- `/api/health` 暴露数据库与 AI 状态。
