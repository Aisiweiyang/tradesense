# 11 · AI 安全边界

> 第十步起 AI 参与「需求字段解析」：AI 只提议（白名单+原文依据校验），
> 状态机裁决落库，详见 [docs/23-AI-Intake.md](23-AI-Intake.md)。

## 定位

AI 是**可选增强层**。`AI_PROVIDER=none`（默认）时全部 P0 功能可用——需求解析用规则引擎、摘要用确定性模板、报价用程序计算。

## 支持的提供方

| provider | 配置 | 说明 |
| --- | --- | --- |
| `none` | 无 | 确定性模式（默认） |
| `openai_compat` | OPENAI_BASE_URL / OPENAI_API_KEY / OPENAI_MODEL | OpenAI / DeepSeek / 通义 等兼容接口，`response_format=json` |
| `ollama` | OLLAMA_BASE_URL / OLLAMA_MODEL | 本地模型，无需密钥 |

## AI 允许做什么

- 对**规则引擎已提取的字段之外**提出补充提取建议（field 白名单内）→ 存为 `needs_confirmation`，人工确认后才生效；
- 润色回复草稿英文正文（保持事实与数字不变，润色后追加一条人工确认项）；
- 解释匹配结果、总结客户历史（路线图）。

## AI 禁止做什么（代码强制）

- ❌ 编造 SKU / 价格 / 库存 / 认证 / 交期 / 客户信息；
- ❌ 修改确定性报价的任何数字；
- ❌ 绕过匹配硬条件（认证/价格上限/交期/市场）；
- ❌ 覆盖人工锁定字段；
- ❌ 自动发送任何消息（草稿永远止步于人工批准）。

## 工程约束（`services/ai/__init__.py`）

1. 输出必须匹配 JSON Schema（`response_format=json_object` + 本地再解析）；
2. 字段白名单：补充提取仅接受预定义字段名；
3. 类型校验（Pydantic/手工验证）后才使用；
4. 超时 25s、重试 ≤1；
5. 任何失败 → 静默回退确定性结果（模板正文 / 无补充字段），并保证核心流程不受影响；
6. 调用入口集中（`ai_suggest_extra_slots` / `ai_polish_reply`），便于审计与禁用。

## 提示词约束

System prompt 明确要求：只提取文本明确陈述的内容；润色时保持事实/数字/承诺完全不变；仅返回指定 JSON 结构。

## 测试

`test_api.py::test_full_core_flow` 等全部测试在 `AI_PROVIDER=none` 下运行，验证无 AI 时闭环完整可用；连接器、报价、匹配均不依赖 AI。
