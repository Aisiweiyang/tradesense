# 12 · 权限与数据隔离

## 多租户隔离

- 所有业务表带 `org_id` 外键；
- 用户 JWT 携带 `org_id`，请求侧**没有任何接口允许客户端指定组织**；
- `OrgScope` 依赖从令牌解出组织，路由内所有查询强制 `Model.org_id == scope.org_id`；
- 跨组织读取/修改一律 404（不泄露存在性）；有专门测试覆盖（`test_org_isolation`：他司产品列表为空、单查/改 404）。

## 认证

- `POST /api/auth/login` → JWT（HS256，默认 7 天有效期）；
- 密码 PBKDF2-HMAC-SHA256，240,000 轮 + 随机盐（纯标准库实现，无 bcrypt 版本兼容问题）；
- 首次初始化走 `POST /api/auth/bootstrap`（仅当系统无用户时可用，防止重复初始化）；
- 401 统一返回 `{"error":{"code":"unauthorized|invalid_token|bad_credentials"}}`，前端 401 自动清除令牌回登录页。

## 角色

当前版本：`owner / manager / member / viewer` 字段已建模，owner 为组织创建者；细粒度权限矩阵在 P2 路线图（数据模型已预留 roles 表）。

## 审计日志（audit_events）

记录：登录、初始化、询盘创建、需求人工修改、匹配执行、报价创建/定价/批准/拒绝、回复生成/批准、导入提交、连接器创建/同步/删除、演示种子等。

- 详情 JSON 写入前对敏感键脱敏（password/token/secret/api_key/authorization/config_json → `***`）；
- 前端「审计日志」页可检索查看。

## 其他安全措施

- 上传限制：仅 .csv/.xlsx/.xlsm，≤10MB；导入必须预览确认；
- 外部内容按不可信输入处理：连接器原文原样存档（raw_content），解析仅读取文本；表单接口有蜜罐与最短长度校验；
- 统一错误信封不暴露堆栈；服务器 500 仅记日志；
- 响应头：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`；
- CORS 白名单仅本地开发来源（生产按需配置）；
- 日志脱敏：连接器同步日志不记录消息正文，只记录计数与状态；
- 连接器最小权限：邮箱只读、只生成草稿；不自动发送任何外部消息；
- SQL 注入防护：全部查询经 SQLAlchemy 参数化。
