# 09 · 搜索与排序算法

## 两阶段检索

### 阶段 1：候选召回（recall）

- 查询构造：产品概念的全部同义词（中英）+ 概念码 + 归一化材质；
- 对每个在售产品计算 token 重叠（name_en/name_zh/category/keywords/description/material/spec）：
  - 完整 token 命中 +1，前缀包含 +0.5，中文连续片段命中 +2；
- 无概念或零命中时回退为全量候选（小规模产品库下由重排序兜底）；
- 取 top 60 进入阶段 2。可选向量检索为增强项（pgvector），不可用时自动降级（当前版本即降级模式）。

### 阶段 2：确定性重排序（rerank）

权重可配置（`DEFAULT_WEIGHTS`，机构级可覆盖），满分 100：

| 维度 | 权重 | 判定 |
| --- | --- | --- |
| category | 20 | 概念码完全相等=满分，否则 0（询盘未明确概念时按文本相关性计 40%） |
| price_fit | 14 | 阶梯价 ≤ 目标价 95% 满分；超目标价线性衰减 |
| certification | 12 | 客户要求的认证全部具备=满分 |
| quantity_vs_moq | 10 | qty≥MOQ 满分；低于 MOQ 按 ratio 惩罚（**可协商项，非硬淘汰**，但必须在 unmet 中可见） |
| material | 10 | 相等满分，不一致 30% |
| customization | 8 | 产品支持 logo/print/oem=满分 |
| color / spec | 6+6 | 命中满分，未标注 60-80%，不一致 20-30% |
| lead_time | 6 | 生产周期 ≤ 要求天数 |
| destination | 3 | 市场备案检查 |
| supplier_reliability | 3 | 供应商可靠性 0-1 直接折算 |
| freshness | 2 | 资料核验新鲜度（365 天线性衰减） |

排序稳定性：`(-score, product_id)`，同分确定性一致（有测试）。

## 硬条件（Hard Filters）

以下条件不满足 → `excluded=true` 并**必须显示原因**，不允许用其他分数掩盖：

1. 客户明确要求的认证缺失（如 LFGB）；
2. 阶梯价高于客户目标价（唯一命中时以「替代方案」形式展示 `is_alternative=true`，保留成交可能）；
3. 生产周期超过客户要求的交付天数；
4. 产品备案市场（markets）不含目的国；
5. 禁用材质（来自否定表达，如 no plastic）。

返回结构（前端逐条渲染）：

```
total_score      总分
scores{}         每维 {score, max, detail}
met[] / unmet[]  满足/未满足的判定描述
excluded + exclude_reason   淘汰原因（人话）
data_snapshot    匹配时的价格阶梯/数据来源/核验时间
```

## 智能追问

每轮最多 1 个主问题 + ≤3 个次要项，评分：

```
法规/认证阻塞        100   （食品接触类无 FDA/LFGB 要求）
报价阻塞字段          90-95 （product/quantity/incoterm/目的国；CIF/DDP 缺目的港）
严重矛盾              80
属性信息增益     40+gain   gain = split_score×40
                       split_score = 1 - 2·|0.5 - p|（p=候选产品集中该属性非空占比）
目标价缺失            30
交期缺失              25
定制缺失              20
问过的问题         -60   （ClarificationLog 去重，不重复骚扰）
```

每个候选问题附 `reason`（"为什么建议问这个"）。人工补齐字段后对应追问自动关闭。
