## 一、这是个什么项目

TradeSense（外贸询盘助手）是给小型外贸团队用的询盘到订单工作台：客户询盘进来 → 自动解析成结构化需求 → 匹配产品 → 程序算报价 → 生成回复草稿 → 成交后核验单证、导出复核包，全程有漏斗和看板。

- 技术栈：FastAPI + SQLAlchemy 2 + Alembic + SQLite（可换 PostgreSQL）；React 18 + TypeScript + Vite + Tailwind + React Query + Recharts；Playwright。
- 结构：Python 后端、React/TypeScript 前端和 5 条浏览器 E2E；当前测试结果见 CHANGELOG，测试矩阵见 docs/13。
- 三条铁律：**价格 100% 程序计算**（AI 只建议、人工确认）；**系统永不自动发消息**；**数据按组织隔离**，跨组织一律 404。

## 三、代码结构与导读

```
backend/
  app/
    main.py            启动：建目录、create_all 兜底、挂路由、静态资源
    database.py        engine + SessionLocal（SQLite 自动建父目录）
    config.py          环境变量（SECRET_KEY、DATABASE_URL、SEED_DEMO_DATA…）
    deps.py            get_current_user / OrgScope（org_id 从令牌来，请求伪造不了）
    rbac.py            权限矩阵（只许增量加键）+ require_role 依赖
    models/            14 个模型文件；base.py 有 OrgMixin/TimestampMixin/TZDateTime
    schemas/           Pydantic 入参/出参，全部集中在一个 __init__.py
    api/routes/        14 个路由文件，api/__init__.py 统一挂载（前缀 /api）
    services/          全部业务算法，路由层保持薄
    seed/              演示数据（16 个场景询盘、42 产品、货件单证、知识库、汇率）
    alembic/           迁移；每张新表一个 revision
  tests/               21 个文件 210 个测试；conftest 用内存 SQLite + 事务回滚
frontend/
  src/pages/           20 个页面，一个页面一个文件
  src/api/client.ts    fetch 封装：token 注入、统一错误信封、401 踢回登录
  src/components/ui.tsx Card/Badge/EmptyState/ErrorState 等基础件
  src/i18n/            中英词典，缺 key 回退中文
  e2e/                 5 条 E2E 链路（token 由登录接口取，localStorage 注入）
scripts/               start_dev（一键启动）、capture_pages.mjs（Playwright 无头截图）、backup_db（备份）
```

**业务算法都在 services 里**，改功能先找对应文件：报价 `quotation.py`、匹配 `matching.py`、追问 `clarification.py`、需求状态 `requirement_engine.py`+`requirement_service.py`、单证提取 `doc_extractor.py`、单证规则 `doc_rules.py`、漏斗 `funnel.py`、汇率 `fx.py`、比价 `compare.py`、草稿 `reply_drafts.py`、复核包 `review_package.py`、渠道 `connectors/`+`ingestion.py`。

**一封询盘的旅程**：POST /api/inquiries → `ingestion/询盘路由` 解析文本（`slot_extractor` 抽字段 → `requirement_engine` 更新状态机）→ 写首个阶段事件（漏斗）→ `matching.persist_match_results` 出候选 → `quotation.compute_quote` 算价（汇率经 `fx.resolve`）→ 人工批准才 is_formal。

**改代码前必须知道的约定**：所有业务表带 org_id 且查询必须过滤；错误一律走 `{"error":{code,message,details}}` 信封；敏感操作调 `services/audit.py` 的 `audit()`；新表要同时写 Alembic 迁移（nullable 跟随既有迁移的宽松写法）。

## 四、怎么开发

环境要求：Windows 11、Python 3.13、Node 24，无 Docker、不依赖外网密钥。

```powershell
# 首次：一键起（自动建 venv、装依赖、迁移、灌演示数据）
scripts\start_dev.bat
# 后端 http://127.0.0.1:8001   前端 http://127.0.0.1:5173
# 端口冲突就先设 $env:TRADESENSE_BACKEND_PORT / TRADESENSE_FRONTEND_PORT

# 测试（改完必跑）
cd backend;  .venv\Scripts\python -m pytest -q
cd frontend; npx vitest run
cd frontend; npx tsc -b                                  # 类型零错误
cd frontend; $env:E2E_TOKEN=(登录接口取的token); npx playwright test   # 5 条
```

增量开发套路：**改模型 → `alembic revision` 写迁移 → `alembic upgrade head` → 改 schema → 改 service/route → 补测试 → 前端对应页面 → 三套测试全绿 → commit**。提交信息中文一行主题 + 要点；每完成一个功能点就 commit + push，不要攒大包。

写测试的入口都在 `backend/tests/`：API 测试用 `client` + `auth_headers(client)` 夹具（登录拿真 token），纯算法测试用 `db` + `org` 夹具直调 service；第二个组织用 `other_org` 夹具测隔离。

## 五、怎么调试

### 后端

```powershell
# 调试时建议手动起，带 --reload，日志直接在终端也能看
cd backend
.venv\Scripts\python -m uvicorn app.main:app --port 8001 --reload
# 日常后台运行的日志在 logs\backend.log
```

- **调接口**：先拿 token 再带上头：

```powershell
$body = '{"email":"demo@tradesense-demo.cn","password":"demo1234"}'
$tk = (Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8001/api/auth/login -ContentType "application/json" -Body $body).access_token
Invoke-RestMethod -Uri http://127.0.0.1:8001/api/analytics/funnel -Headers @{ Authorization = "Bearer $tk" }
```

- **打断点**：VS Code 里直接对 pytest 或 uvicorn 附加调试——`launch.json` 用模块名 `pytest`（参数 `-q tests/test_xxx.py -k 名字`）或 `uvicorn`（module 模式，args 填 `app.main:app --port 8001`）。
- **直接查数据**：

```powershell
cd backend
.venv\Scripts\python -c "from app.database import SessionLocal; from sqlalchemy import select; from app.models import Inquiry; db=SessionLocal(); [print(i.id, i.stage) for i in db.scalars(select(Inquiry)).all()]"
```

- OpenAPI 文档在 <http://127.0.0.1:8001/docs>，可以鼠标点着调所有接口。

### 前端

- `npm run dev` 自带热更新，改 TSX 即时生效；`npx tsc -b` 随时查类型；
- 登录令牌存在 localStorage 的 `tradesense_token`，调试时可在控制台 `localStorage.getItem("tradesense_token")` 或手工塞 token；
- 接口报错先看 Network 面板的错误信封，`error.code` 和后端抛错处一一对应，直接全局搜字符串定位。

### 数据库与迁移

- 看版本：`cd backend; .venv\Scripts\python -m alembic current`；
- 如果报"table already exists"：先备份并对照实际表结构及迁移版本定位原因，不应直接用 `alembic stamp head` 掩盖未执行的迁移；
- 需要干净的演示环境时，指定新的 `DATABASE_URL` 与 `UPLOAD_DIR` 后运行 `init_db.py`，避免把现有业务目录用作测试库。

### E2E 与截图

- E2E 卡住时加 `--headed` 看浏览器动作：`npx playwright test --headed -g 链路2`；
- 整套页面截图：`cd frontend && node ../scripts/capture_pages.mjs`（Playwright 等待 networkidle + 关键元素，稳定不空图）；
- 截图脚本走 `#token=` 本地引导注入登录态（仅 localhost 有效）。

### 常见报错对照

| 症状 | 原因与处理 |
| --- | --- |
| 启动报 `[Errno 10048]` 端口占用 | 有旧进程没关：`Get-NetTCPConnection -LocalPort 8001` 找 PID 杀掉，或换 TRADESENSE_*_PORT |
| push 超时/连接重置，但浏览器能开 GitHub | DNS 路由问题：`git -c http.curloptResolve="github.com:443:140.82.112.3" push origin main` |
| `UNIQUE constraint failed: users.email`（测试） | 测试里手动建了 `other_org` 夹具已有的 owner2@test.cn，删掉手动建用户那段 |
| 接口 403 | 权限矩阵不够（rbac.py 查能力对应角色），换 owner 账号或加权限键 |
| 前端 401 踢回登录 | token 过期，重新登录即可 |
| 截图几 KB 且内容空 | 无头浏览器渲染没完成，重跑 |

## 六、我个人怎么使用

完整的按键级操作在 [21-使用手册](21-使用手册.md)，这里是我的最小日常：

1. **开机**：双击 `start_dev.bat`，开 <http://127.0.0.1:5173>，用 `demo@tradesense-demo.cn / demo1234` 登录；
2. **来询盘**：粘进「询盘 → 粘贴/录入询盘」，看完整度和中文摘要；缺什么按「追问」问客户，客户回复粘进「对话」；
3. **报价**：「匹配」选产品 →「报价」选成本来源（阶梯价或某供应商），利润率一填，点「计算并创建草稿」，看过明细和风险没问题时「批准」；多条报价可勾选「合并为报价单」导出对客 PDF；
4. **回客户**：「回复」选场景勾知识库条目生成草稿，批准后复制全文，自己去邮箱发；
5. **成交后**：「单证工作台」建货件、传两版发票看差异、处理异常，最后「导出复核包」存档；
6. **周末看板**：「数据看板」看漏斗哪一阶段掉得最狠；
7. **备份**：`python scriptsackup_db.py` 一键备份到 `backups\`（保留 10 份）；改密码在「设置 → 修改密码」。
