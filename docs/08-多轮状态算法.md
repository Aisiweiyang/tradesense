# 08 · 多轮需求状态算法

## 目标

不能把聊天记录简单拼接。每个需求字段是一个**独立状态机**，跨多轮消息维护当前有效值，并保留完整历史与来源。

## 字段与槽位

字段集（`services/fields.py` 单一事实源）：product / material / color / spec / quantity / target_price / destination_country / destination_port / incoterm / packaging / customization / certification / lead_time / payment_terms / sample / shipping_method / notes。

每个槽位记录：

```
raw_value      客户原话片段
value          展示值（如 "1,000 pcs"）
normalized_value  归一化值（如 "1000"、国家 ISO2、概念码）
unit           pcs / ml / days / 币种
status         状态机（见下）
confidence     提取置信度（字典 0.95 / 正则 0.85-0.9 / 低置信 0.6）
source_message_id   值来自哪条消息
history_values [{value, message_id, status}]  旧值链
locked / confirmed                  人工锁定 / 人工确认
```

## 状态机

```
unknown ──提取到值──▶ active
active  ──新值──▶ 旧值置 replaced，新值 active（变更写 history）
active  ──同值──▶ reaffirmed（刷新来源与置信度，不产生噪音变更）
任意    ──"any color / 无所谓"──▶ unconstrained（视为已知信息，参与完整度）
任意    ──同一消息内两个值（如 green and navy blue）──▶ conflicting（needs human）
conflicting ──客户/人工明确单一值──▶ active（记录 conflict_resolved）
低置信(<0.75) ──▶ needs_confirmation（待人工确认后才算数）
locked  ──任何自动更新──▶ 拒绝覆盖，记录 locked_ignored 并提示人工复核
```

## 覆盖语义示例（规格验收场景）

```
客户1: I need 500 blue stainless-steel bottles.
客户2: Actually, make them black, increase the quantity to 1,000, and ship to Hamburg.
客户3: Also quote on FOB basis. LFGB is mandatory. Target USD 4.5/pc.

最终状态:
  product=insulated_bottle  material=stainless steel
  color: blue → black       quantity: 500 → 1,000
  destination_port=Hamburg  incoterm=FOB  certification=LFGB
  target_price=4.5 USD/pcs  完整度 85%
```

历史记录保留 `blue`、`500`（哪条消息、何时、由谁）。

## 归一化层（`normalization.py`）

- 颜色 30+（含 zh），材质 40+（304/ss304/18-8 → stainless steel 304）；
- 币种符号/缩写/中文；国家 60+（含中文与常用别称）；港口 70+（别名/中文 → 标准港名+国家推断）；
- 认证 25+（FDA/LFGB/CE/RoHS/BPA-free/Prop65/EC1935/2004…，单词边界防误报如 "required"≠red）；
- 产品概念 11 类、中英同义词、复数与连字符容错（vacuum insulated bottles / 保温杯 → insulated_bottle）；
- 数量解析优先级：显式单位(pcs/sets) > k 后缀(5k) > 过滤价格/日期/容量后的最大数字；
- 价格解析支持区间与多币种（USD 2-3/pc、预算 12 元/个）；
- 日期解析（within 45 days / end of October / before Nov 1 → 天数）。

**原始表达一律保留**，归一化只附加标准形式。

## 人工权威

- 人工修改：`PATCH /inquiries/{id}/slots`（值经同一归一化器，confirmed=true，confidence=1.0）；
- 可选 `lock=true`：锁定后任何自动更新被拒绝（locked_ignored + 界面提示复核）；
- 解锁：`DELETE /inquiries/{id}/slots/{field}/lock`；
- 人工补齐矛盾字段时，对应 open 状态的追问自动关闭。

## 完整度（可解释）

权重：product 20 / quantity 15 / 目的国 10 / 目的港 10 / 术语 10 / 材质 8 / 认证 7 / 规格 5 / 包装 5 / 目标价 5 / 交期 5 = 100。
输出 `{score, confirmed[], missing[], conflicting[]}`；前端同时给出「当前不能正式报价的原因」清单（product/quantity/目的国/术语缺失；CIF/DDP 类缺目的港；食品接触类无食品级认证；存在矛盾字段）。
