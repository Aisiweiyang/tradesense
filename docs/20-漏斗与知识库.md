# 20 · 销售漏斗 · 知识库 · 汇率配置

三个第六阶段能力的口径与用法说明。

## 销售漏斗（九阶段）

数据源：`inquiry_stage_events`（append-only 事件表）。询盘创建、阶段变更、won/lost 终态同步都会写事件；算法在 `backend/app/services/funnel.py`，端点 `GET /api/analytics/funnel`（登录即可看本组织）。

阶段主链：`new → qualified → clarifying → quoted → sample → negotiating → won`，另有 `lost` / `dormant` 两个分支终态。

### 口径（重要）

- **数量 count**：询盘当前所处阶段。
- **触达 reached**：曾经进入过某阶段的询盘数 = 有对应 `to_stage` 事件的数量；无任何事件的存量询盘按"当前阶段触达"兜底计入。
- **转化率 conversion_to_next**：主链相邻两站 reached 的比值（分母为 0 时为 `null`，不猜测）。
- **停留时长**：每次进入阶段 S 的时刻，到该询盘下一次阶段事件的间隔；之后没有变更的（仍在 S）按"至今"时长计入。这对仍在阶段的询盘是**右删失**——观测时刻截断，中位数因此是真实停留时长的**保守下界**，与 Salesforce 等 CRM 的"阶段耗时"报表口径一致。刻意不引入 Kaplan-Meier 修正：保持可解释、可手算。

前端在数据看板顶部以横向条形 + 明细表展示；点击任一阶段条形/行可查看该阶段的口径说明。

## 知识库（最小版）

`knowledge_documents` 表（title/content/tags），端点 `GET/POST/PATCH/DELETE /api/knowledge`：读 `knowledge.read=viewer+`，写 `knowledge.write=member+`；搜索 `?q=` 同时匹配标题/内容/标签（子串）；按组织隔离。

### 在回复草稿中引用

生成草稿时在 `extra.knowledge_ids` 传入条目 id（可选多个）：

```json
POST /api/replies/generate
{ "kind": "first_reply", "tone": "formal",
  "extra": { "inquiry_id": 1, "knowledge_ids": [1, 3] } }
```

行为：

- 正文末尾追加英文引用块（`> 标题: 摘录`，摘录超 220 字符截断）；
- `facts_used` 增加 `知识库#<id>` 条目，来源可追溯；
- `needs_confirmation` 追加"知识库内容已引用，请人工核对"；
- 引用块在 AI 润色**之后**追加，润色不会改写引用内容；
- **不传 `knowledge_ids` 时草稿行为与原来完全一致**；跨组织或不存在的 id 会被静默跳过（不报错、不引用）。

种子内置 5 条示例（LFGB/EC 1935/2004、IPPC 木包装、FDA 与 CA Prop 65、样品与快递惯例、付款方式风险梯度），可在 `/knowledge` 页面增删改查。

## 汇率配置（手工，不接外部 API）

完整口径与报价取用优先级见 [19 · 多供应商比价与合并报价单](19-比价与报价单.md#汇率配置手工不接外部-api)。速记：

1. 用户显式指定的 `exchange_rate` > 2. 汇率表（设置页维护，`/api/fx`，manager+）> 3. 回退 1:1 + missing 提示；
2. 币种对按字母序规范化存储（录入 USD/CNY=7.2 存 CNY/USD=1/7.2），反向查询读时取倒数、不做二次舍入；
3. 汇率缓冲 2% 只在真实跨币种时叠加；运费/税率仍为内置估算并在风险区提示。
